# SignatureTutor

A single-file web app: type your name, get a set of realistic hand-drawn
signature styles to choose from, then practice the one you like with a
printable workbook and an on-screen tracing mode.

See `PLAN.md` for the in-progress rework of the signature engine and why it
was needed.

## Running it

`SignatureTutor.html` is fully self-contained — open it directly in a
browser (double-click, or `file://...`) and it works. It loads React,
ReactDOM, and Babel Standalone from a CDN at runtime and transpiles its own
JSX in-browser, so there is no build step for *using* the app.

## Editing the app

`SignatureTutor.html` is a **generated file** — do not hand-edit the code
inside its `<style>`/`<script>` blocks. The real sources live in `src/`:

| Source | Contents |
|---|---|
| `src/app.css` | All styling, inlined into the page's single `<style>` tag |
| `src/vendor/perfect-freehand.js` | Vendored `perfect-freehand` (variable-width ink outlines); MIT |
| `src/glyph-data.js` | Generated cursive letterform data — see below; do not hand-edit, re-run `tools/extract-glyphs.mjs` instead |
| `src/engine-core.js` | The deterministic centerline stroke engine (`buildSignature`, `SIG_STYLES`) — pure JS, runs under bare Node too |
| `src/signature-react.jsx` | React rendering layer on top of the engine (`SignatureSVG`, ink/line render modes, stroke-order arrows, sequential draw-in animation) |
| `src/screens-1-3.jsx` | Name / Style / Preview screens |
| `src/screens-4-6.jsx` | Hub / Worksheet / Practice / Export screens |
| `src/app.jsx` | Top-level `App` component, routing, state, persistence |

After editing anything under `src/`, regenerate the HTML:

```sh
node build.js
```

and commit both the `src/` change and the updated `SignatureTutor.html`.
`build.js` has no dependencies (plain Node, no npm install needed) and is
idempotent — running it twice in a row produces no further diff. It works by
replacing the content between matching marker comments
(`// @inline:<id>:start` / `:end`, or `/* @inline:<id>:start */` for CSS) in
the HTML with the current contents of the corresponding `src/` file; see the
comment at the top of `build.js` for how new source files get their own
block added automatically.

## The signature engine (Phase A)

Signatures are built from real cursive letterform skeletons, not a generic
per-character wiggle: `src/glyph-data.js` (generated by
`tools/extract-glyphs.mjs` from the SVG fonts vendored into `tools/fonts/`)
holds a centerline polyline per character, which `src/engine-core.js` chains
into continuous per-word pen strokes, decorates with lead-ins/tails/
underlines per style, optionally degrades toward a scrawl, shears for slant,
fits to the viewBox, and finally renders as variable-width "ink" via
`perfect-freehand`. Everything is seeded from `(name, style, variant)` via a
single deterministic RNG draw — see the "DETERMINISM DISCIPLINE" comment at
the top of `src/engine-core.js` before changing the pipeline.

To regenerate `src/glyph-data.js` after changing the fonts in `tools/fonts/`:

```sh
node tools/extract-glyphs.mjs
```

Verification tools (not shipped, dev-time only):
- `tools/test-engine.mjs` — bare-Node determinism/coverage/sanity checks.
- `tools/screenshot.mjs` — Playwright visual verification (writes to the
  gitignored `tools/screens/`).

- **Hershey Script fonts** (public domain — originally produced at the US
  National Bureau of Standards by A. V. Hershey) and **EMS Allure**
  (SIL Open Font License; a derivative of Allura by Rob Leuschke, SVG
